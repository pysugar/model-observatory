# 任务与代理主控选型依据

核验日：2026-10-16。范围是报告建议与证据补充，没有修改 OpenClaw / Hermes 配置、调用付费模型或做中文实验。

## 证据分工

- `routing-evidence.json` 从报告原有 166 条记录中选取 Sol 6.1 的 10 条档位记录，保留原 ID、费用口径和来源。Vulcan 是 23 道二进制重建题、每档每题一次，经 Codex CLI 运行；AA 是 v4.3.2 的 2026-10-14 冻结快照。两者不能混算。
- Sol medium → high：Vulcan 多通过 1 题，平均 API 等价费用变化约 -17.2%；AA 综合指数增加 2，公布的加权任务费用变化约 +52.4%。这些不是高档位必定更省或更贵的因果证明。
- high、xhigh、max 在该 Vulcan 样本的功能通过数相同；代码质量分不完全相同，不能声称整体能力无差别。最高档的额外费用和耗时须由具体交付收益支持。
- 官方 Sol 页面确认默认 medium、支持 low 至 max、不支持 none / minimal；工具调用走 Responses。模型 ID 与 effort 分开设置。
- Claude 型号与档位依官方 effort 指南。截图 Sonnet 5 high、Opus 5 high 是官方起点与任务推断；不得把 Sonnet / Opus 5.5 的实测分移给 5。Opus 5.5 的复杂设计 high 是本报告建议，API 默认仍为 medium。
- Code review、根因定位、回归测试生成和架构设计没有这些候选的完整同题档位对照。Vulcan Code quality 是被生成代码的评分，不是被测模型找出缺陷的能力。测试生成与实际执行分开验收。

## 主控判断

Sol 6.1 high 是工程工作为主时的推荐起点；日常混合任务从 medium 起步。它们是结合公开证据、官方定位与任务成本作出的推断，没有在用户的 OpenClaw / Hermes 环境中证明最优。Luna 留给可校验轻任务，Astra 作为能力或时间敏感任务的升级比较对象。

框架文档只用于说明可配置字段与路由边界：OpenClaw 模型 / 代理 / 会话有优先级；Hermes 支持全局和按模型 reasoning，辅助调用可能复用主模型。未核验用户安装版本、实际 provider、协议或 effort 是否生效。Hermes 文档中 slash 命令的部分优先级示例存在表述差异，因此报告不提供未验证的运行时命令。

可先以 20–30 个代表任务进行 medium / high 配对验证，关键失败复跑；固定输入、工具权限、时间与费用上限，统计完整完成率、错误工具调用、人工介入、端到端 P50 / P95 和包含失败重试的每成功任务总成本。该样本规模不保证统计显著。中文理解及成稿另做人工评价。
