如何理解“1M 上下文”和多模态支持
上下文上限代表可容纳量，不保证长文档推理或信息召回质量。Argon 的 1,048,576 是输入、思考、输出共享窗口；Flash / Flash-Lite 列的是输入上限，输出另有 65,536 上限。GPT 的窗口为 1,050,000；Claude 4.6 及以后为 1M / 128k；本次核验的 Opus 4.5、Sonnet 4.5、Haiku 4.5 为 200k / 64k。旧评测页面的窗口标注不覆盖当前官方规格。
表中只列这些通用 API 模型的原生输入和文本输出。GPT / Claude 的产品或工具可以处理其他媒体，但不应据此把通用模型标为原生音频、视频输入；Gemini 的音频/视频理解也不等于能生成音频/视频。图像生成、TTS、Live 与视频生成另有专用模型。

  
用同一组用量假设比较 API 预算
这是费用情景，不是实测成本。每次请求的 token 数相同，不能保证不同模型完成同一任务会使用同样的 token。

  

    
    
    
    
    
    
  
费用＝[输入×(1−缓存占比)×输入价＋输入×缓存占比×缓存读取价＋(可见输出＋推理)×输出价]÷1,000,000×请求数。缓存比例表示已有命中，不包含建立缓存的写入/存储成本。工具、检索、区域加价、税费、失败重试与人工复核另计。超出窗口或同步输出上限时不估价。

  
Haiku 5.5 >100k 的整次请求阶梯价、GPT >272k 的长上下文价会自动应用。Argon 的 long decode 是单独模式，本计算器按同步上限检查。Google 优惠结束情景只变动已公布的 Google 价格，其余仍按核验日。

  
订阅用户更应该比较“验收后的完整交付”
不能把榜单上的 $0.33 理解为套餐扣了 $0.33，也不能从 API 单价推导“max 消耗几次额度”。实际比较应记录：任务是否完成、总等待时间、人工修改时间、重试次数，以及产品界面实际显示的额度变化。额度规则未核验时保持未知。

    一个通用的五步实测选型流程
    1. 先固定真实业务任务、输入材料、工具权限、输出预算与验收标准。
    2. 选 2–3 个候选模型，先测默认或 medium / high 档；预算允许的高难度任务，可加入 xhigh 作为能力上限参照。
    3. 若质量不达标，优先比较补齐上下文、升一档与换异构模型；若质量达标，再比较单任务总费用和完成时间。
    4. 分开记录正确性、交付完整性、格式合规率与人工返工量；保留所有失败和超时，不能只算成功样本。
    5. 用同题配对、随机顺序与多次重复确认小差异；中文内容用盲评补充英文公开榜单。
    API effort、OpenAI reasoning.mode=pro、产品 Ultra、服务 Fast/Ultrafast 是不同控制项。原数据集中的 Ultra 作为编排变体保存，不折算成 max。OpenAI 定义 · Claude 定义 · Gemini 定义

      回答是否合意
      Text Arena 让用户匿名比较成对回答，反映表达与人类接受度；不等于事实或代码正确率。类别、票数和置信区间仅在来源提供时参考，本轮不填新数字。
      FAQ · 配对偏好方法
      
      
      任务是否省心
      Agent Arena 从真实 agent 会话作因果追踪，估计组件选择相对基线的净改善（Net Improvement）；不是配对投票，也不是绝对任务成功率。原始百分比与净改善是不同量，不互换。
      因果评估方法 · 2026-10-12 信号定义
      
      
      结果是否正确
      Factuality-adjusted Text / Search 引入事实核验，应与纯偏好排名分开，并核对事实性权重。代码另看具名编程评测和真实任务测试；架构设计暂无直接可比公开成绩。

      成本是否值得
